  2. Dashboard widget card is copy-pasted 9 times
  Every widget opens with:
  color: "#1c1c1c"
  radius: Theme.radius
  border.color: Theme.sptr
  border.width: 1
  A single WidgetCard.qml base component eliminates this. Widgets would just be WidgetCard { ColumnLayout { ... } }.

  ---
  3. Hardcoded dark colours not in Theme
  #1c1c1c, #2a2a2a, #252525 appear throughout the dashboard but don't exist in Theme.qml. Theme.bgnd is #141414. Adding Theme.bgnd2/Theme.bgnd3 makes them themeable without
  hunting through 9 files.

  ---
  4. Theme.acct is #141414 — same as Theme.bgnd
  border.color: Theme.acct is used in the scratchpad, bar module, and elsewhere. It renders as invisible since it matches the background. Either acct should be a visible
  accent colour or those call-sites should use a different token.

  ---
  5. The poll-process pattern is duplicated ~15 times
  Timer { onTriggered: { proc.running = false; proc.running = true } }
  Process { id: proc; stdout: StdioCollector { ... } }
  The bar already solved this with CommandMonitor.qml but the dashboard reimplements it from scratch in ClockWidget, NetworkWidget, StatsWidget, MediaWidget, and
  LockSurface. Either import CommandMonitor into the dashboard (moving it to a shared location) or make a thin PolledValue.qml that wraps the pattern.

  ---
  6. FileView + debounce save duplicated in ScratchpadWidget and TodoWidget
  Both have identical FileView { blockLoading: true } + Timer { id: saveTimer } + fv.setText(...) logic. A PersistentFile.qml helper (or a plain JS function) would keep the
  pattern in one place.

  ---
  7. Uptime fetched in two places independently
  ClockWidget polls mavencore uptime every 60 s. LockSurface polls the same command every 500 ms with its own separate Process. Moving uptime into a Singleton (like
  Time.qml already is for the clock) would let both read the same value.

  ---
  8. LockSurface has a hardcoded wallpaper path
  LockSurface.qml hardcodes file:///mnt/DATA/Pictures/CURRENT_BLUR. The Wallpaper component correctly exposes wallpaperPath as a property. LockScreen.qml should expose a
  blurPath property and thread it through.

  ---
  9. The LazyLoader overlay pattern is repeated verbatim in 4 places
  Dashboard, Scratchpad, Launcher, and NetworkManager all share the same structure:
  property bool open: false
  IpcHandler { function toggle() { open = !open; loader.active = true; if (!open) closeTimer.start() } }
  Timer { id: closeTimer; onTriggered: loader.active = open }
  LazyLoader { id: loader; PanelWindow { WlrLayershell.keyboardFocus: open ? Exclusive : None ... } }
  QML can't easily inherit Scope behaviour, but extracting the toggle/timer logic into a shared OverlayBase using Component/Loader is feasible and would remove ~30 lines of
  identical boilerplate from each component.
